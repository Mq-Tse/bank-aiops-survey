# GitHub 银行 AI Ops 开源项目调研平台 - 产品需求文档

## Overview
- **Summary**: 构建一个展示和分析 GitHub 上银行/金融行业 AI Ops 开源项目的信息平台，提供项目对比、技术分析、选型建议和趋势洞察，帮助银行运维团队快速了解业界开源生态。
- **Purpose**: 银行 AI Ops 领域信息分散、缺乏系统性梳理。本平台通过聚合 GitHub 上的优质开源项目，提供一站式的选型参考和技术决策支持，降低银行技术团队的调研成本。
- **Target Users**: 银行 SRE 工程师、运维架构师、技术管理者、DevOps 工程师、AI Ops 研究者

## Goals
- 系统性梳理 GitHub 上与银行 AI Ops 相关的开源项目
- 提供多维度的项目对比（Stars、许可证、技术栈、成熟度、适用场景）
- 针对银行行业特点，给出具体的选型建议和落地参考
- 分析银行 AI Ops 技术趋势，指导长期技术规划
- 覆盖从基础可观测性到 AI 智能体的完整技术栈

## Non-Goals (Out of Scope)
- 不提供开源项目的代码托管或二次开发服务
- 不做实时数据更新，项目数据为调研时点的快照
- 不包含商业闭源 AI Ops 产品的分析
- 不提供部署实施或技术咨询服务
- 不做项目活跃度的动态追踪

## Background & Context
- AI Ops（智能运维）在银行领域的核心价值：告警降噪、根因分析、自动化修复、成本优化
- 银行特有的技术约束：安全合规要求高（PCI-DSS、等保）、系统稳定性要求极高、多技术栈并存（Mainframe、分布式、微服务）
- 开源生态正在成为银行 AI Ops 的重要选项，eBPF、OpenTelemetry、AI Agent 等新技术加速落地
- 国内银行对国产化和自主可控有强烈需求

## Functional Requirements
- **FR-1**: 展示银行 AI Ops 开源项目的详细目录，包括项目名称、GitHub 链接、Stars 数、许可证、技术栈、核心功能描述
- **FR-2**: 提供项目分类和标签筛选能力（可观测性、告警管理、日志分析、AI 智能体、流程编排等）
- **FR-3**: 支持多维度项目对比视图，包括功能覆盖、成熟度、银行适用场景评分
- **FR-4**: 提供面向银行的选型建议，按使用场景（核心观测、告警管理、AI 智能体、流程编排等）推荐组合方案
- **FR-5**: 展示技术趋势分析，包括 eBPF、AI Agent、开源标准治理等演进方向
- **FR-6**: 每个项目需标注银行应用价值和典型落地场景

## Non-Functional Requirements
- **NFR-1**: 所有数据基于 GitHub 公开信息，标注数据采集时点
- **NFR-2**: 项目分析需客观中立，基于公开文档和社区反馈
- **NFR-3**: 选型建议需明确区分"推荐"和"备选"，并说明适用前提
- **NFR-4**: 支持中英文双语展示（项目名、技术术语保留英文，描述用中文）

## Constraints
- **Technical**: 数据来源为 GitHub 公开 API 和文档，不涉及私有数据源
- **Business**: 仅覆盖开源项目，不涉及商业产品评价
- **Dependencies**: 依赖 GitHub API 的可用性和 Rate Limit

## Assumptions
- 银行 AI Ops 关注的核心领域包括：可观测性（监控/追踪/日志）、告警管理、AI 根因分析、自动化运维、流程编排
- 调研的项目需具备一定社区活跃度（Stars > 500）
- 项目需有明确的金融/银行应用价值或已在金融行业有落地案例
- 考虑到国内银行环境，标注项目是否支持离线部署和中文支持

## Acceptance Criteria

### AC-1: 项目覆盖完整性
- **Given**: GitHub 上存在银行 AI Ops 相关开源项目
- **When**: 用户访问项目目录
- **Then**: 至少展示 12 个项目，覆盖可观测性、告警管理、日志分析、AI 智能体、流程编排 5 大类
- **Verification**: `programmatic`
- **Notes**: 调研时点（2026年8月）的 GitHub 数据

### AC-2: 信息准确性
- **Given**: 已采集的项目数据
- **When**: 用户查看项目详情
- **Then**: 每个项目的 GitHub 链接、Stars 数、许可证、技术栈与 GitHub 实际数据一致（允许 ±10% 的 Stars 误差，因数据持续增长）
- **Verification**: `programmatic`

### AC-3: 分类合理性
- **Given**: 项目已采集
- **When**: 用户查看项目分类
- **Then**: 每个项目都被归入至少一个功能分类，分类逻辑清晰且符合行业共识
- **Verification**: `human-judgment`

### AC-4: 选型建议质量
- **Given**: 项目分析完成
- **When**: 用户查看选型建议章节
- **Then**: 针对不同银行场景（核心观测、告警降噪、AI 诊断、流程编排等）给出明确的项目推荐组合，且推荐理由充分
- **Verification**: `human-judgment`

### AC-5: 趋势分析深度
- **Given**: 调研完成
- **When**: 用户查看趋势洞察
- **Then**: 至少覆盖 3 个技术趋势方向（如 eBPF、AI Agent、开源标准治理），每个方向有具体项目支撑和落地价值说明
- **Verification**: `human-judgment`

### AC-6: 对比可用性
- **Given**: 多个项目
- **When**: 用户查看项目对比表
- **Then**: 提供至少 10 个维度的对比（Stars、许可证、语言、功能覆盖、银行场景、成熟度、部署方式、安全特性等），对比结构清晰
- **Verification**: `programmatic`
